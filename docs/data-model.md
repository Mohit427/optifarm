# Data model

The prototype uses static JSON files (no database). They live in
[`frontend/src/data/`](../frontend/src/data) and are shared: the frontend bundles them for
offline use, and the backend reads the same files (`DATA_DIR`).

## Crop record — `crops.json` (10 crops)

Paddy, groundnut, maize, tomato, chilli, ragi, cotton, sugarcane, brinjal, black gram.

| Field | Type | Notes |
|---|---|---|
| `id` | string | Stable key used everywhere (`paddy`, `blackgram`, …). The vision model may only return these. |
| `name_en`, `name_ta`, `name_hi` | string | Display names. |
| `season` | string[] | `Kharif`, `Rabi`, `Zaid`, `Annual`. |
| `sowing_window` | `{start_month, end_month}` | 1–12; may wrap the year (e.g. Nov–Jan). |
| `duration_days` | int | Sowing to harvest. Equals the sum of stage days. |
| `spacing_cm` | `{row, plant}` | Row × plant spacing. |
| `water_need_mm_total` | int | Indicative seasonal water need (display fact). |
| `growth_stages` | `{stage, days, kc}[4]` | `initial`, `development`, `mid`, `late`; FAO-56 style Kc (development `kc` = value reached at its end = Kc mid; late `kc` = Kc end). |
| `heat_tolerance_max_c` | number | Above this, a heat-stress alert is shown. |
| `suitable_soils` | string[] | Soil keys, translated in the UI (`clay`, `red_loam`, `black_cotton`, …). |
| `stop_irrigation_days_before_harvest` | int | Final-stage irrigation cut-off. |
| `harvest_indicators` | `{en, ta, hi}: string[]` | Harvest-timing signs. |
| `post_harvest_tip` | `{en, ta, hi}: string` | One storage/handling tip (post-harvest loss). |
| `seed_description` | string | Visual description given to the vision model as a hint. Not shown as a fact. |
| `seed_image` | path | Illustrated sample image in `frontend/public/seeds/`. |
| `source_note` | string | Provenance; shown under the Seed Lens card. |

## Sample field — `fields.json` (3 fields)

Generated by `npm run gen:data` ([`scripts/gen-data.ts`](../frontend/scripts/gen-data.ts)).

| Field | Type | Notes |
|---|---|---|
| `id`, `name`, `name_local` | string | Thanjavur delta (paddy), Pollachi (tomato), Kovilpatti black soil (chilli). |
| `district` | string | |
| `centroid` | `{lat, lng}` | Used for the weather forecast. |
| `polygon` | GeoJSON Polygon | `[lng, lat]` order, closed ring. |
| `area_ha` | number | Computed from the polygon. |
| `suggested_crop_id` | string | |
| `zone_source` | `"sample" \| "simulated"` | `simulated` for farmer-drawn fields. |
| `zones[]` | see below | |

Zone: `{zone_id, label, polygon (MultiPolygon), area_ha, stress_score 0–1, moisture_index 0–1, ndvi, recommended_action_key}`
with `label ∈ critical | moderate | healthy | waterlogged`. Zones are unions of clipped Voronoi
cells ordered along a noisy stress gradient, which gives irregular but spatially coherent
shapes, like classified NDVI/NDMI rasters. Zone areas sum to the field area.

## Weather summary

`GET /api/weather?lat&lng` (and the browser's own fallback) return:

```json
{
  "source": "live | cached | sample",
  "fetched_at": "ISO time",
  "lat": 10.8, "lng": 79.2,
  "daily": [{ "date": "YYYY-MM-DD", "et0_mm": 4.6, "rain_mm": 0, "temp_max_c": 33.5, "temp_min_c": 23.8 }],
  "hourly": { "time": ["YYYY-MM-DDTHH:00"], "shortwave_radiation_wm2": [0, 0, 120] }
}
```

Degradation order: Open-Meteo live → last cached response (browser `localStorage`, backend
`.cache/`) → bundled `weatherFallback.json` re-dated to today.

## Plan record (per day, per zone)

```json
{
  "date": "2026-10-04", "zone_id": "Z1",
  "action": "irrigate | skip",
  "reason_key": "irrigate | rain | no_need | waterlogged | not_sown | pre_harvest | harvested",
  "net_mm": 6.1, "gross_mm": 6.8, "litres": 21010, "kwh": 3.1,
  "start_time": "09:00", "duration_min": 51,
  "solar_window": { "start": "09:00", "end": "16:00" },
  "solar_share": 1.0
}
```

Each day also carries `kc`, `stage`, `days_after_sowing`, `heat_alert`, totals and the solar
window. The plan total includes `solar_share` (share of pump energy inside solar windows).

## Impact record

`methods.{flood|drip|precision}`: `litres_per_ha`, `kwh_per_ha`, `cost_inr_per_ha`,
`solar_share`, `weekly_cumulative_litres_per_ha[]`. The backend adds `savings_vs_flood`.

## Client state (browser only)

`localStorage` keys: `kl.lang` (language), `kl.state.v1` (crop, confirmation, field, sowing date,
current method, pump, edited assumptions), `kl.weather` (last forecast). Chat history lives in
memory only (last 10 messages) and is never stored on the server.
